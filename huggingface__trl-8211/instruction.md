**Title:** Add UDPO loss for noisy preferences to DPOTrainer

## Description

# What does this PR do?

Adds the Unbiased DPO (UDPO) loss to `DPOTrainer` as `loss_type="udpo"`, from our ICML 2026 paper [Unbiased Alignment for Large Language Models with Noisy Preferences](https://huggingface.co/papers/2607.03248). This is the `DPOTrainer` half of #8175, split out as requested there. The `RewardTrainer` half (URM) is in #8210.

UDPO corrects the DPO loss for preference labels flipped with probability ε. This PR implements its normalized form, called α-UDPO in the paper:

$$
\mathcal{L}_{\text{UDPO}} = -\alpha \log\frac{e^{z} + a}{e^{z} + 1}, \qquad a = \frac{\varepsilon}{1 - \varepsilon}, \qquad \alpha = \frac{1 + \sqrt{a}}{1 - \sqrt{a}}
$$

where $z$ is the DPO logit. Unlike `"robust"`, its optimum stays unbiased when ε is overestimated (Corollary 4.7 of the paper). The constant α keeps the maximum gradient magnitude at 1, as for the DPO loss. This is the variant that the paper recommends to practitioners; the unnormalized loss (Eq. 14) only differs by this constant.

```python
from trl import DPOConfig

training_args = DPOConfig(loss_type="udpo", label_smoothing=0.4)
```

Changes:

- No new `DPOConfig` field. ε is read from the existing `label_smoothing`, which `"robust"` already uses as the flip probability.
- `DPOTrainer`: a `"udpo"` branch in the loss loop. The log term is computed in log space as `logaddexp(logsigmoid(z), log(a) + logsigmoid(-z))` for numerical stability, and `label_smoothing=0.0` recovers `"sigmoid"`. `"udpo"` is added to the losses that support `f_divergence_type`, since it only depends on the chosen-rejected reward difference. A `ValueError` is raised when `label_smoothing` is outside [0.0, 0.5), because a ≥ 1 no longer prefers the chosen completions.
- Docs: a row in the loss table of `dpo_trainer.md` and a `paper_index.md` entry.
- Tests: `"udpo"` in `test_train_loss_types`, the loss value against the closed form (single eval example, compared with the logged reward margin), and the `label_smoothing` range check.
